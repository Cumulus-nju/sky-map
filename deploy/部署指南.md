# 上线部署指南 —— 把「天光云影」做成真网站

目标：一个**免费**的公网网址，同学在任何地方用手机就能投稿、看地图，
组织者能在后台改稿删稿。全程不需要自己买服务器。

用到的服务：

| 服务 | 干什么 | 费用 |
|---|---|---|
| [GitHub](https://github.com) | 存代码 | 免费 |
| [Streamlit Community Cloud](https://share.streamlit.io) | 跑网站，给 `xxx.streamlit.app` 网址 | 免费 |
| [Supabase](https://supabase.com) | 存投稿和照片（免费层 500MB 数据库） | 免费 |

> **为什么不能直接把现在的代码传上去？**
> Streamlit Cloud 的容器**重启就清空文件系统**，而本地版把投稿写在
> `data/submissions.jsonl` 里。不接数据库的话，同学投的稿会不定期消失。
> 本项目已经做好存储层抽象：配了 Supabase 环境变量就自动走云端，
> 没配就还是本地文件——同一套代码，两种运行方式。

## 一、准备 Supabase（存数据）

1. 注册 <https://supabase.com> → **New project**
   - 区域选 `Southeast Asia (Singapore)`，国内访问快一些
   - 数据库密码随便设一个，**记下来**（后面基本用不到，但别丢）

2. 等 1~2 分钟项目初始化完成，左侧 **SQL Editor → New query**，
   把 `deploy/supabase_schema.sql` 的内容整个粘进去 → **Run**。
   看到 `Success. No rows returned` 就对了。

3. 左侧 **Project Settings → API**，复制两个值：
   - **Project URL** → 形如 `https://abcdefgh.supabase.co`
   - **service_role secret** → 一长串 `eyJ...`

   > ⚠️ 一定要用 **service_role**，不是 `anon`。
   > 表开了 RLS 且没建策略，只有 service_role 能读写。
   > 这个 key 权限很大，**只放在服务端 Secrets 里**，
   > 不要写进代码、不要提交到 GitHub、不要发群里。

### 一之二、**已经上线过的话**：补跑一次 SQL（人气投票）

2026-10-06 加了「人气投票」（`pages/投票.py`），它需要两张新表
（`voters` / `votes`）和三个数据库函数。

**已经部署过的站点必须补这一步**，否则一打开投票页就会报
「投票表连接不上」，投票直接不可用：

1. 打开 Supabase 项目 → 左侧 **SQL Editor → New query**
2. 把 `deploy/supabase_schema.sql` **整个文件**再粘一次 → **Run**
   （全篇都是 `create table if not exists` / `create or replace`，
   重复执行是安全的，不会动已有的投稿数据）
3. 确认文件末尾那段「人气投票」里，`voters` 表有 `name` 与 `name_h` 两列

> 为什么必须由数据库来管票数：**"每人最多 3 票"不能靠前端把按钮灰掉** ——
> 刷新页面、或者两条请求同时发出去，就能投出第 4 票。
> 真正的约束在 Postgres 函数 `cast_vote()` 里：一个事务内完成
> "查身份 → 查重 → 计数 → 写入"，并用 `pg_advisory_xact_lock` 按人串行化。

## 二、把代码推上 GitHub

```
git init

git branch -M main
```

## 三、部署到 Streamlit Cloud

1. 打开 <https://share.streamlit.io>，用 GitHub 账号登录
2. **New app** → 选你的仓库
3. **Main file path** 填 `app.py`
4. 点 **Advanced settings → Secrets**，粘进：

```toml
SUPABASE_URL = "https://你的项目.supabase.co"
SUPABASE_KEY = "eyJhbGciOi...你的 service_role key"

# 务必设置：否则云端重启后任何人都能重新设置管理员口令
# （设了它也只是"口令就位"，后台**每次打开仍要手动输一遍**）
ADMIN_PASSWORD = "换成一个你自己的口令"

# 人气投票的加盐哈希用盐（2026-10-06 新增）
# ⚠ 不配就会用代码里的默认盐 = 公开值 = 等于没加盐。必须换成自己的随机串。
# ⚠ 一旦开始投票就**不要再改**，否则同学会被判成"与登记信息不一致"。
VOTE_SALT = "换成一串 40 位随机字符"
```

> 🧂 生成 `VOTE_SALT`（PowerShell 一行，正好 40 位）：
> ```powershell
> $c='abcdefghijklmnopqrstuvwxyz0123456789'; -join (1..40 | % { $c[(Get-Random -Max 36)] })
> ```
> ⚠ 不要用 `(48..57)+(97..122) | Get-Random -Count 40`：字符池只有 36 个，
> 而 `Get-Random -Count` 超过池子大小时只返回全部 36 个 ⇒ 实际只有 36 位。

5. **Deploy**，等 2~3 分钟，拿到网址 `https://xxx.streamlit.app`

> ⚠️ **改了 Secrets 必须手动 Reboot 才生效**：App 右侧 ⋮ → **Manage app** → **Reboot**。
> 只保存 Secrets 而不重启，容器里跑的还是旧配置（这一点在 2026-10-02 排查线上白屏时
> 又被印证了一次：**页面显示的内容取决于进程里加载的模块/配置，不是磁盘上的文件**）。

> 🔐 **`ADMIN_PASSWORD` 请用专用口令，别用数据库密码**。它只用来登录管理后台，
> 跟 Supabase 无关；一旦用数据库密码，等于把数据库凭证多复制了一份到后台入口。
> 忘记口令不会丢数据：改 Secrets 里的这一行再 Reboot 即可。
>
> 🚪 **登录闸门（2026-10-09 修）**：后台**每次打开都要输口令** —— 登录状态只存在
> 当前会话里，刷新/换浏览器/换设备都要重输，没有"记住我"。
> 之前配了 `ADMIN_PASSWORD` 反而会**自动登录**（同步口令时顺手把会话标成已登录），
> 云端每次 Reboot 后的第一个访问者不用输口令就能进后台；现已修掉，
> 回归测试 `tools/test_admin_login.py`。
> ⚠ 没登录时侧边栏**不显示**「🔧 管理后台」入口，所以请把 `https://你的站点/管理员`
> 存成书签。

## 四、迁移已有的投稿（可选）

如果你在本地已经收了一些稿，把它们搬到云端。**在自己电脑上**跑：

```powershell
cd 项目文件夹
$env:SUPABASE_URL="https://你的项目.supabase.co"
$env:SUPABASE_KEY="eyJhbGciOi...service_role key"

python tools/migrate_to_supabase.py --dry-run   # 先看要传什么
python tools/migrate_to_supabase.py             # 真传
```

脚本会逐条上传照片、写投稿记录，最后回读校验条数一致。

## 五、上线后怎么用

| 谁 | 网址 | 能做什么 |
|---|---|---|
| 同学 | `https://xxx.streamlit.app` | 投稿、看地图。**不能**改删任何人的稿 |
| 你 | 同上 → 侧边栏「🔧 管理后台」 | 输口令进后台，改位置/文字/奖项、删稿、批量清理 |

后台三个页签：

- **⚠️ 待复核**：自动定点可疑的稿子，地图上点一下正确位置就能校正
- **✏️ 逐条修改**：改标题、作者、天象、奖项、经纬度，也能重生成缩略图
- **📋 总表 / 批量删除**：全量表格 + 批量删除 + 清空示例数据 + 重新生成地图

## 七、已知限制与建议

1. **照片直接存数据库（base64）**：几百幅的规模完全够用（免费层 500MB）。
   如果预计上千幅，建议改成 Supabase Storage 存文件、库里只存路径。
   届时只需改 `store.py` 里的 `SupabaseStore`，上层不用动。

2. **免费层会休眠**：Streamlit Cloud 的免费应用长时间没人访问会睡，
   下一个人打开要等 30 秒左右唤醒。活动期间问题不大。

3. **上传体积**：Streamlit 默认单文件上限 200MB。原图很占空间，
   建议在征稿说明里提醒同学**压到 5MB 以内**再传。

4. **并发写**：投稿记录是"整表读→改→整表写"，几十人同时投稿理论上会互相覆盖。
   征稿期并发不高，实际没问题；真要做高并发得换成逐条写库。

5. **管理员口令忘了**：本地删掉 `data/admin.json` 重设；
   云端在 Secrets 里改 `ADMIN_PASSWORD`，重新部署即可。
