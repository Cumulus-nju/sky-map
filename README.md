# 天光云影 · 校园天空打卡点地图

「天光云影」南京大学校园天空摄影大赛的**核心成果工具**（对应策划案第十节）。

同学投稿时在地图上点一下机位、传上原图，后台自动定点、汇总，一键生成
**可复制、可分享的交互式打卡点地图**，覆盖**鼓楼 / 仙林 / 苏州**三校区。

---

## 一、它解决什么

| 策划案要求 | 本工具的实现 |
|---|---|
| 同学提交照片时附位置信息 | 投稿页里**地图点选机位**（最准）；也支持照片 EXIF GPS、文字描述（"北大楼前草坪"）自动匹配 |
| 后台汇总、自动定点 | `map_build.py` 把每条投稿归一化成 WGS84 经纬度，落点在校区外的自动标「待复核」 |
| 可交互的地图 | Leaflet 单文件 HTML：三种底图、按校区/天象/关键词筛选、点列表联动地图、筛选状态可复制成链接 |
| 可复制、可分享 | 在线版只需打包 `data/exports/` 整个文件夹；另有照片内嵌的离线单文件版，断网也能开 |
| 标注编号/缩略图/最佳时段/机位提示 | 打卡点自动编号聚类，弹窗含代表作品、拍摄时间、天象、机位手记与拍摄建议 |
| 地图范围以鼓楼为主，可扩展仙林、苏州 | 三校区一套配置，切换即可；底图已抓好 |

## 二、快速开始

```

# 3) 随时重新汇总

python map_build.py --offline  # 照片内嵌的单文件离线版
```

### 🗳 人气投票（2026-10-06 新增）

规则集中在 `vote_config.py`：时间窗 **2026-10-07 — 2026-11-30**、每人 **3 票**
且必须投给不同作品、只有**状态为「已入围」**的投稿才上墙（示例数据永不进墙）。

同学端填 **姓名 + 学号/工号 + 手机号**（三项都必填）确认身份后投票；
**投票期间不显示票数**，截止后自动公示；票数明细只有管理后台能看（第四个页签）。

> 🔐 学号与手机号在库里**只存加盐哈希**（盐 = Secrets 里的 `VOTE_SALT`）+ 掩码，

> 并用 `pg_advisory_xact_lock` 按人串行化；前端把按钮灰掉是拦不住刷新和并发的。
>
> ⚠ 已经上线过的站点要用投票功能，**必须到 Supabase 再执行一遍
> `deploy/supabase_schema.sql`**（新增 `voters`/`votes` 表），见部署指南「一之二」。

> **想部署成公网网站？** 见 [`deploy/部署指南.md`](deploy/部署指南.md) ——
> GitHub + Streamlit Cloud + Supabase，全免费，不用自己买服务器。

## 三、投稿流程（同学视角）

1. 打开投稿页，选校区；
2. 在**街道底图**上点一下自己拍照站的位置（点错了再点一次覆盖）；
3. 传照片 —— 若手机原图带 EXIF，会自动读出拍摄时间与器材，有 GPS 也会提示；
4. 填作品名、姓名、拍摄时间、天象、机位手记 → 提交；
5. 页面立即回显「自动定点结果 + 来源 + 匹配到的地标」，落点可疑的会提示待复核。

> 提醒同学：**别用微信压缩图**，EXIF 会被抹掉；用原图或直接从相册上传。

### 三种定点方式（按可信度优先）

| 方式 | 来源 | 精度 | 说明 |
|---|---|---|---|
| 地图点选 | `picked` | ★★★ | 直接得到经纬度，无需地理编码，**推荐** |
| 照片 EXIF | `exif` | ★★ | 零操作；微信传输会丢失 |
| 文字描述 | `text` | ★ | 中文二元组相似度 + 停用词清洗，模糊匹配地标词典 |

落点在校区边界外、或文字匹配置信度低时，标记 `loc_verify=True`，地图上显示「待复核」，
并进入管理后台的「待复核」队列。

## 四、管理后台

侧边栏「🔧 管理后台」（登录后才出现），或直接访问 `/管理员`。

**首次使用**会让你设置一个口令（存 `data/admin.json`，只存加盐哈希）。
部署到云端时，请在 Secrets 里配 `ADMIN_PASSWORD` —— 否则云端重启后文件系统被清，
页面会退回"首次设置"状态，等于后台没锁。

四个页签：

- **⚠️ 待复核**：逐条列出落点可疑的投稿，在图上点一下正确位置即可校正并解除标记；
- **✏️ 逐条修改**：改标题/作者/天象/奖项/经纬度，可用原图重新生成缩略图；
- **📋 总表 / 批量删除**：全量表格、导出 CSV、批量删除、清空示例数据、重新生成地图；
- **🗳 人气投票**：勾选作品「标记入围」（决定谁上投票墙）、看票数排行、
  投票人明细（姓名 + 学号/手机号掩码 + 投了哪几幅）、导出流水、撤销异常投票。

## 六、底图与坐标（关键坑，已处理）

三种底图，一键切换：

| 底图 | 坐标系 | 用途 |
|---|---|---|
| 🗺 OSM 街道 | WGS84 | 默认；中文标注清楚，鼓楼/仙林覆盖好，**点位最准** |
| 🛰 高德卫星 | **GCJ-02** | 看真实地形；苏州校区（OSM 几乎空白）主要靠它 |
| ⛰ 矢量建筑 | WGS84 | 用 OSM 建筑轮廓画的深色底图，**断网可用**，瓦片失败自动降级 |

### 关于 GCJ-02 纠偏

高德瓦片是 GCJ-02 坐标系，与 WGS84（OSM / 手机 GPS）**差 500~640 米**——
不处理的话照片点位会整体飘到隔壁街区。本工具的处置：

1. `map_build.py` 按校区算出 EPSG:3857 平面下的偏移量（米），传给前端；
2. 前端在 `getTileUrl` 里平移瓦片网格，并给点位/建筑轮廓加同样的补偿；
3. 切到卫星底图时视野同步平移，避免点位被推出屏幕。

偏移量已用像素级校验确认（`tools/verify_align.py` 把 OSM 建筑轮廓叠在卫星影像上，
红框精准套住目标建筑）。

> **实测结论（2026-09）**：CARTO 已返回 "API KEY REQUIRED" 占位图、Esri 返回 403、
> 天地图需 key —— 均已排除。可用的是 OSM、高德、OpenTopoMap。
> 复测：`python tools/check_tiles.py`

对应策划案「投稿与统计组」「地图制作组」：

- **投稿与统计组**：征稿期间每周跑一次 `python map_build.py --csv`，看 `unresolved` 列表

- **颁奖前**：确认获奖作品的 `award` 字段（`一等奖`/`二等奖`/…），地图弹窗会自动标出。
- **发布**：12 月上旬推送在线版链接 + 打印版海报（用地图「全览」截图或矢量底图导出）。

## 十一、已知限制

1. **在线瓦片依赖外网**：断网/内网环境请用离线单文件版（矢量底图）。
2. **投稿页的卫星模式未纠偏**：表单页面用 Folium，卫星图层仅供看地形；
   点选机位请用默认街道底图（WGS84，与数据同坐标系）。
3. **苏州校区地标为估算值**：新校区 OSM 数据缺失，见第七节。
4. **云端并发写**：投稿记录是"整表读→改→整表写"，几十人同时投稿理论上会互相覆盖。
   征稿期并发不高，实际没问题；真要高并发得改成逐条写库。
5. **示例数据是合成图**：`demo_*` 仅为演示，正式征稿前跑 `python reset_data.py` 清掉。
6. **免费层会休眠**：Streamlit Cloud 的应用长时间没人访问会睡，下次打开要等约 30 秒唤醒。
   接上 Supabase（Streamlit Cloud + Supabase）后，云端站点与本地一致。
7. **地图视野锁在 frame 内**：只能往里放大、缩不出去。视口比框"扁"时，
   横向仍会露出框外一点（几何上无法避免）。手机等窄屏会把最小缩放级算得更小，
   也就是能多缩一点 —— 宁可留余量，也不要让同学被卡住。
8. **苏州的 frame 是人工标定的**：含东侧厂区/园区，见下方「地图外框」一节。

## 十二、地图外框（frame）：校园 + 周边，视野锁定

投稿页和成品地图上那个方框 = 每个校区的 `frame` 配置，**不是** `bbox`：

| | 是什么 | 用途 |
|---|---|---|
| `bbox` | 手校的"校园大致范围"，偏紧 | 只用于判断落点是否可疑（待复核） |
| `frame` | **校园全部建筑 + 四周 150 m 缓冲**，长宽比按各校区实际形状自适应 | 画方框 + **锁定地图视野**：只能往里放大，缩不出去 |

| 校区 | frame 尺寸 | 长宽比 | 依据 |
|---|---|---|---|
| 鼓楼 | 1550 × 1719 m | 0.902 | OSM 298 栋建筑实测范围 + 150 m |
| 仙林 | 1939 × 2491 m | 0.778 | OSM 297 栋建筑实测范围 + 150 m |
| 苏州 | 2400 × 2200 m | 1.091 | ⚠ OSM 无建筑数据，依卫星影像人工标定 |

> **为什么改**：老 `bbox` 是手估的，鼓楼西侧切掉 4 m、东侧切掉 149 m，
> 仙林西侧切掉 133 m、东侧切掉 148 m —— 同学正常站在校园里点选会被**误标「待复核」**。

重算 / 校验：

```powershell
python tools\compute_frames.py            # 按建筑实测范围打印建议值
python tools\compute_frames.py --verify   # 校验：框必须包住全部建筑
python tools\compute_frames.py --pad 200  # 换缓冲宽度
```

> ⚠ **苏州这个框是人工标定的**：影像上看校园建筑群大致落在 120.371~120.387，
> 当前框的东界取到 120.3936，会把东侧的厂区/园区一并包含进来。
> 这是**有意保留**的（2026-10-01 用户确认）。核对图见
> `data/tile_check/suzhou_frame_check.png`（外框+地标全景）、
> `suzhou_frame_crop.png`（框内放大）、`suzhou_east_edge.png`（东界带经度刻度）。

## 十三、苏州校区配准问题（2026-09-28 结论：不做）

`Desktop\南苏建模数据_备用\` 里有南大苏州校区的 CFD 建模数据：
935 个精确建筑足迹（来自资产处《苏州校区平面图》2024-03），几何质量很高。

**但没有绝对地理坐标** —— GLB 元信息写着 `"scale": "Approximate metres, not surveyed"`，
SketchUp 导出时未带地理参考，模型原点 (0,0) 对应哪个经纬度无从得知。

试过自动配准（以"建筑不落在水面上"为判据做平移搜索）：**失败**。该区域农田、
工业区、水网交错，判据被 2 km 外的工业园区骗走，最优解落在工业厂房上。

**决定不做**，原因：建模数据只影响底图外观，而同学投稿是"在地图上点选机位"，
精度由同学自己保证；EXIF GPS 路径也不受影响。收益与成本不成比例。

若将来要用（例如做 3D 校园展示），仍缺的只有一样：模型原点的真实经纬度。
工具已备好：`校准苏州校区.bat`（http://localhost:8502）—— 人工把建筑轮廓拖到
卫星影像上对齐，一键保存到 `data/suzhou_georef.json`。
底图缓存：`python tools/_cache_suzhou_base.py`。
